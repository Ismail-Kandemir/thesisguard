# Phase 4E-8 Multi-Section Margins / Section Ownership Audit

## Scope

This audit originally proved the false negative without changing production
behavior. Phase 4E-8A now keeps the same synthetic OOXML fixture as a regression
fixture for section-aware margin validation.

## Fixture

- File: `tests/fixtures/comu/food-technology/experimental/multi-section-margin-synthetic.docx`
- Origin: `synthetic-ooxml`
- Mode: `regression`
- Created from: `full-correct.docx`
- Mutation: adds an intermediate paragraph-level `<w:pPr><w:sectPr>...</w:sectPr></w:pPr>`
  section whose left and right margins are intentionally wrong.

The final body-level `<w:sectPr>` keeps the original correct margins.

## OOXML Evidence

Generated by `node tests/audit/multiSectionMarginAudit.cjs`:

- Total `sectPr`: 3
- Paragraph-level `sectPr`: 2

- Wrong intermediate section margins:
  - left: `1000` twips = `1.76` cm

## Root Cause

Before the fix, `parseDocumentXml` stored only a single
`NormalizedDocument.pageMargins` object. `parsePageMargins` read all OOXML
`sectPr` nodes and kept only the last one. `MarginValidator` read only
`document.pageMargins[side]`, so it had no section ownership or per-section
margin information.

Phase 4E-8A adds `NormalizedDocument.pageSections` and validates margins across
all parsed sections while preserving the legacy `pageMargins` field.

## Classification

- Production bug: yes, false negative for multi-section documents.
- Architectural limitation: yes, the domain model only exposes one global page
  margin set.

No production fix is implemented in this phase.
