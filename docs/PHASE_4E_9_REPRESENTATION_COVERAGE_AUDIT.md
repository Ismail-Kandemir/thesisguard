# Phase 4E-9 DOCX Representation Coverage Gap Audit

## Scope

This is an audit-first phase. No production parser, normalizer, validator, rule,
or domain source was changed for this phase.

## Current Corpus Coverage

The current experimental corpus covers:

- full golden 46-rule success path
- targeted negative fixtures for indentation, typography, line spacing, table
  alignment, margins, footer page-number alignment, and page-number sequence
- style inheritance and based-on paragraph style resolution
- docDefaults and theme font resolution
- automatic heading numbering through `numbering.xml`
- split runs for headings, captions, references, keywords, and body text
- complex REF field cached result text reconstruction
- marked TOC and balanced multi-paragraph complex TOC result ownership
- section-aware margins, including intermediate wrong, final wrong, and all
  sections correct

## Rule Family Coverage Map

- Typography and paragraph formatting use body paragraph/run extraction,
  effective formatting, style inheritance, docDefaults, and theme mapping.
- Heading rules use paragraph style IDs, visible paragraph text, numbering
  normalization, and heading normalization.
- Margins and page-number sequence use section properties. Margins are now
  section-aware; page-number sequence uses section boundaries and `pgNumType`.
- Page number presence/alignment uses header/footer XML parts and PAGE fields.
- Required sections, order, summary word count, and keywords use normalized body
  paragraphs and section detection.
- Tables, figures, captions, and in-text references use body visual structure,
  caption text, drawing/table detection, and paragraph text reconstruction.
- Abbreviation list requirement uses normalized body text and abbreviation list
  detection.

## Ranked Coverage Gaps

1. Tracked changes (`w:del` / `w:ins`) - High
   - Affects visible text reconstruction, typography, section detection,
     headings, references, word counts, and abbreviation facts.
   - Common in real Word documents with Track Changes enabled.
   - Current parser has no acceptance/rejection state model.

2. Text boxes / DrawingML / VML text - High
   - Visible text may live outside ordinary paragraph/run traversal.
   - Can affect required sections, captions, references, and typography.
   - Needs careful trust boundary because Word rendering semantics vary.

3. Footnotes/endnotes - Medium
   - `word/footnotes.xml` and `word/endnotes.xml` are not read by the package
     reader.
   - Could affect references or abbreviation facts, but may be an intentional
     body-only trust boundary.

4. AlternateContent - Medium
   - `mc:Choice` and `mc:Fallback` can duplicate or hide equivalent content.
   - Current descendant traversal may include more than the Word-visible branch.

5. Hyperlinks/bookmarks/simple fields - Low to Medium
   - Hyperlink text is included through descendant runs.
   - Bookmarks are non-visible markers and usually safe.
   - Simple fields are covered for TOC/PAGE in parser-level tests, but not every
     body REF/PAGEREF variant is represented.

## Selected Risk

Selected representation: tracked deleted runs (`w:del`) in body text.

Reason: it is common in Word documents, directly affects existing 46-rule
production behavior, is not covered by the corpus, and can be tested with a small
synthetic OOXML mutation without adding a new feature.

## Diagnostic Fixture

- File: `tests/fixtures/comu/food-technology/experimental/tracked-deleted-run-font-size-synthetic.docx`
- Origin: `synthetic-ooxml`
- Mode: `exploratory`
- Created from: `full-correct.docx`
- Mutation: add one tracked deleted run to a normal academic body paragraph.
- Deleted run formatting: Times New Roman, `w:sz="22"` = 11 pt.

The visible accepted-document semantics should ignore deleted text. The original
visible paragraph remains 12 pt and academically valid.

## Classification

False positive confirmed for the visible accepted-document interpretation:
deleted text is no longer visible content, but the production body typography
validator evaluates it as visible body text.

Root cause chain:

`w:del/w:r/w:t` exists in OOXML
→ `parseRuns` reads all descendant `w:r` elements under the paragraph
→ `parseRunText` reads deleted run `w:t`
→ `NormalizedDocument.paragraphs[].runs` contains the deleted run
→ `FontSizeValidator` evaluates it as a visible body run
→ `RuleResult` fails font size

## Trust Boundary

This audit does not define full Track Changes semantics. It only proves that
deleted text is currently treated as visible text. Handling insertions, move
ranges, revision acceptance policy, and mixed revision states should be scoped in
a separate production fix phase.
